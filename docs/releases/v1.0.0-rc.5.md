Fifth release candidate of BlindVault 1.0. It carries the fixes for the review's findings and the review and visual pass of every screen. It is still a pre-release: vaults and backups made with it may not open in a later version, and no migration is planned for them (D177, D194). Before you use it, read [docs/limitations.md](../limitations.md).

What changed since v1.0.0-rc.4:

- the extension: a passkey request from a page no longer holds off the auto-lock, excludeCredentials matches only the site's own passkeys, Confirm takes no click as soon as it shows, an aborted call no longer leaves its request pending, a second request goes to the browser, and an IP address is refused as rpId (D305);
- the `.bvault` reader refuses a final chunk past 65,535 bytes of plaintext, and every CBOR value refuses -0 (D306);
- sync: overlapping blob asks no longer abort an honest sync, an ID asked for again aborts with protocol-error, and a pairing and a re-admission check retired peers before blob units (D307);
- a held blob that does not match its blobId is repaired, and an export leaves it out and names its items; a blob with no citation left is collected (D308);
- Android: an app's passkey goes out only for the rpId its request names, a debug package is out of the privileged allowlist, and autofill trusts a web domain only from the browsers on it (D309);
- every test run restores a backup the published v1.0.0-rc.4 exported (D310);
- in Firefox the extension does not lock with the operating system: its idle API never reports `locked` (D311);
- every screen of the web app, of the extension in Chrome and of the Android app reviewed, with their bugs fixed (D312 to D314), and a visual pass over the existing screens from the UX prototypes (D315).

The service worker is unchanged since v0.1.0.

Served at https://blindvault.allisson.dev.
