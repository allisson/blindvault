Fifth pre-release of BlindVault: vaults and backups made with a 0.x version may not open in a later version, and no migration is planned for them (D177). It is the first release deployed to Cloudflare Pages (D228, D230), the Deploy Gate of Phase 6.

What changed since v0.4.0:

- devices: from Settings › Devices, any device of the vault can be renamed, this one, another or a retired one; the newest name wins at the next sync (D74, D118);
- hosting: the build ships `_headers` with the content security policy and the other security headers sent by the server, `frame-ancestors 'none'` and `Cross-Origin-Opener-Policy` included, and a static `404.html`, so an unknown path answers 404 instead of the app (D195, D229);
- release: what is deployed is the release's attested archive, after its attestation is checked, and the served files are checked against the release (D230).

The service worker is unchanged since v0.1.0.

Served first at https://blindvault.pages.dev. https://blindvault.allisson.dev moves to Cloudflare Pages once this release's check passes; an installed copy then takes this build after confirmation, and keeps its vault (D63, D191).
