Seventh pre-release of BlindVault: vaults and backups made with a 0.x version may not open in a later version, and no migration is planned for them (D177). It brings Phase 7b (essential UX, after BlindPass), for another hands-on test of the interface before the Security Gate of Phase 8 (D244). Before you use it, read [docs/limitations.md](../limitations.md).

What changed since v0.6.0:

- navigation: icons on the phone's bottom navigation (Items, Trash, Settings), New item as the phone header's action and Lock in its "…" menu, a type filter above the list, and counts beside All items, each folder and the Trash (D245);
- list: each row shows an avatar with the template's icon, a subtitle read only from fields that are not secret, and Copy for a Login's password; on a phone, items fall under their first letter (D246);
- item detail: a header with the avatar and chips for the template, host, folder and tags, fields in titled cards, Duplicate, History and Move to trash in a "…" menu, and a shown seed phrase as a numbered grid (D247);
- TOTP: a ring beside the code shows the seconds left, amber from 10 s and red from 5 s, with the seconds also in text (D248);
- password strength: a meter in the editor and a Weak badge on the detail for an item's password; it informs and never blocks a save (D249);
- feedback: toasts for copy, save, move to the trash and restore; on a phone a confirmation is a bottom sheet; an empty vault shows first steps; a render error locks the vault and clears the clipboard before its failure screen (D250);
- keyboard: ↑/↓ and J/K move through the list, ↓ moves from the search into it, Esc clears the search, Ctrl/⌘+Enter saves the editor, and the generator has a length slider (D251).

The service worker is unchanged since v0.1.0.
