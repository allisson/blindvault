Fourth release candidate of BlindVault 1.0. It adds the Android credential provider and autofill service, and is the candidate the Release Gate's reproducible build and external review are checked on (D276). It is still a pre-release: vaults and backups made with it may not open in a later version, and no migration is planned for them (D177, D194). Before you use it, read [docs/limitations.md](../limitations.md).

What changed since v1.0.0-rc.3:

- the Android app answers passkey requests from Credential Manager for a privileged browser on the allowlist of release signatures, taken from Google's apps.json and never downloaded, and signs or saves only on the tap in its provider window (D301, D302);
- it serves apps whose domain's assetlinks.json binds them, and passwords (D303);
- the Android autofill service fills a login only after the user unlocks and taps it in the provider window (D304);
- About's check fits each platform: the Android app points to the release's Android section and the unzipped APK's `assets/web`, the extension to the unpacked store package; the export's status names only the Recovery Phrase the file opens with, not the file's name;
- the release body names the APK to install: the unsigned one is for verification only and does not install.

The service worker is unchanged since v0.1.0.

Served at https://blindvault.allisson.dev.
